# Durable evidence-link history — partial AM-05.02

KnowledgeRepository provides loadEvidenceLinks(ctx) and recordEvidenceLinks(ctx,expectedStorageRevision,evidenceSnapshot,command,commandId). The command is the accepted EvidenceLinksCommand: exact current claim ref, expected logical link-set revision and bounded literal support/challenge/quotation selectors. New writes load current claims from the OWN Knowledge operational DB under the project lock, not from caller Knowledge. The separate link aggregate has its own storage CAS. Accepted domain selector/quote/digest/clean/current/purpose/family validation is reused, with its existing64-link/512-history/2MiB history and bounded Evidence snapshot/ancestry limits. Atomic record/audit/outbox/ack preserves contrary/removed links and predecessor history. No claim assessment changes.

The EvidenceState input MUST be a current authenticated authorized snapshot supplied by the host, with relevant current consent/rights/Identity gates. This library does NOT authenticate it, read original bytes, verify scanner quality, or atomically fence external source permissions. Synthetic domain snapshots in tests are not live-source qualification. Copies/source families still follow the accepted domain analysis and are not extra corroboration. No Evidence DB/root is opened or shared; only link selectors/family/fingerprint captures are stored in Knowledge's own DB, not the complete source snapshot.

Reads return detached {revision,state,knowledgeRevision}, historical data only. New writes validate their captured source snapshot inside the owning transaction. Explicit exact historical command replay returns ORIGINAL refs; it does NOT revalidate the caller's newly supplied source snapshot, current claim edition or historical selector usability. Its fingerprint binds operation, actor kind, purpose, storage expectation and command, deliberately not the source snapshot. Replay is NOT a fresh source attestation or new action permit. Current-source review requires a separate authorized current Knowledge/Evidence observation through the accepted reviewEvidenceLinks pure API. An empty set means no captured links, never verified absence or completeness.

Authority and current stored-history validation precede cache. SDK lock precedes Knowledge/link reads; no import/overwrite/delete/reset/eviction route. Lost COMMIT acknowledgement is UNKNOWN; explicit identical replay after fresh authority checks only. Host must bound snapshot ingress/CPU/heap before calling: synchronous cloning/validation is not a sandbox or preemptible. All begun SQL is awaited; driver/transaction/concurrency limits are host responsibilities. Retained aggregate editions consume additional database space.

The opt-in IdentityKnowledgeRepository guards both new methods with the accepted fresh stored fixed whole-history resource/investigate/purpose policy; use it exclusively where required and never fall back on denial/unknown. Identity/Knowledge observations remain sequential, not distributed permission fencing. Host login proofing/config/time, consent/rights and current source transport remain separate. PGlite tests do not establish independent PostgreSQL-session contention, TLS/failover/crash/production, HTTP/UI/browser/AT/live qualification. No schema/contracts/pin/provider/send/publication/payment changes. PAM stays at foundation.
