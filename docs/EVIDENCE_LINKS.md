# Private Evidence links — partial AM-05.02

`@accountability/knowledge-verification/evidence-links` reuses accepted Evidence domain APIs pinned to c9aafd0cc7d655e4dc3f8b5b8b833ef102d4cf2b. It does not duplicate selector/source-family logic. This is pure serialized memory, with no database, network or provider operation. Future persistence must use stable Evidence SQL SDK dce7105a70b42d77afe4cd48d34723331447037c in a separate Knowledge operational database.

`createEvidenceLinksState`, `reviseEvidenceLinks`, `inspectEvidenceLinks`, `assertEvidenceLinksState` and `reviewEvidenceLinks` maintain private immutable link-set revisions per logical claim ID. A new revision must deliberately select an exact current Knowledge claim. Link IDs are unique per set; duplicate relation/selectors deny. Removing a link creates a new set while all prior support and contrary material remains in history. No command ID or persistent idempotency is provided. An empty set explicitly supplies no evidence; it does not retract or erase prior editions.

Selectors bind exact Evidence editions, byte digests, and (when applicable) representation IDs/digests. Existing Evidence validators check clean scan, unresolved integrity failures, current edition/ancestors, purpose and exact text/page/time spans. Text offsets use the upstream representation's JavaScript UTF16 code units with surrogate-boundary checks, NOT UTF8 byte offsets. Page indices are one-based. Media intervals follow the existing Evidence contract. A validated representation/quote is a captured assertion, not a fresh read or proof of original bytes, accurate OCR/media recognition or truth. Tests use actual pinned domain functions and synthetic scanner/representation fixtures, not a production scanner.

Each capture retains the exact family snapshot and dependency fingerprint. Explicit review requires the latest link set, current claim edition, the same purpose, and fresh validation against a caller-supplied Evidence snapshot. A changed Evidence dependency denies review until a deliberate new link revision. Historical inspection returns captured history without claiming current permission, usability or truth. Stored state validation checks shape/history only: a malicious host can forge hashes or supply old snapshots. The host MUST supply a current authenticated authorized Evidence snapshot and current Knowledge/action/consent/rights policy; the pure API does not obtain or authenticate one. Context is trusted host input. Direct possession of serialized state exposes private contents; storage/access controls are the host's responsibility.

Review computes separate `supports`, `challenges` and `quotes` source analyses using accepted Evidence grouping. Copies/shared ancestry cannot inflate distinct support. Missing family data or independence assessments remain unknown (`independentFamilyCount: null`), including an empty set. Current human-authored independence records may change the analysis without changing a selector fingerprint: review recomputes the analysis and returns its actual basis digest. That analysis is a historical observation of the supplied snapshot, not a verification assessment, probability, legal conclusion, editorial approval or action permit. Claims' assessment/procedural/editorial null tracks remain unchanged. Support and challenge groups are not added together; quotation is not support.
