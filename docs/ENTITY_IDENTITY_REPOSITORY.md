# Durable entity-pair judgments — partial AM-05.01

KnowledgeRepository now provides loadEntityIdentities(ctx) and recordEntityIdentity(ctx,expectedStorageRevision,input,commandId). The accepted entity-identity domain input still requires exact current entity refs, lexical pair order, logical pair CAS, explicit same/different/unresolved judgment and rationale. No entity IDs are merged or rewritten and no judgment establishes identity truth.

The pair aggregate lives only in the owning Knowledge operational DB using the existing stable SQL SDK/canonical migration. It has a separate kind/key/storage revision from KnowledgeState. Existing project-lock acquisition precedes BOTH Knowledge and pair-history reads, including cached acknowledgements. New judgments use actual stored current entities in that transaction, never caller-supplied Knowledge snapshots. Atomic pair history/audit/outbox/ack preserves every judgment. Pair storage revision equals total pair records, while the per-pair logical revision/predecessor remains independently validated. Existing512-record/2MiB domain caps reject without eviction; retained aggregate snapshots consume additional DB space. No snapshot overwrite/import/delete/reset interface exists.

loadEntityIdentities returns detached {revision,state,knowledgeRevision}; the Knowledge revision is the independently observed aggregate edition under that same lock. It is metadata, not a permit or a claim of up-to-date identity truth. The pure inspectEntityIdentities function can review a captured state against separately authorized Knowledge; callers must account for different observations. Reads retain historical refs even after entities change. New judgments require current refs; explicit exact historical command replay returns original refs after later entity changes without creating another judgment. Replay validates current host authority and stored history first, but does NOT re-attest the historical judgment against new entities.
