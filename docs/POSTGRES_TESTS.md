# Owning Knowledge PostgreSQL sessions — partial qualification

`npm run test:postgres` uses the actual pinned Evidence SQL SDK, canonical migration and restricted authenticated PostgreSQL17 TCP connections. It accepts only `KVE_TEST_DISPOSABLE_POSTGRES=1` and an administrator `KVE_TEST_ADMIN_URL` targeting an empty loopback database `knowledge_ci`, username postgres, with no query or fragment. Existing ledger state is refused; the fixture never resets a database. Fixed fixture passwords are not deployment credentials. Distinct backend PIDs/session_user are asserted. Ordinary child-process tests reject unsafe configurations before connection.

Five scenarios cover: one owning storage-CAS append winner and one audit/outbox effect; lost actual append COMMIT acknowledgement followed by fresh-pool exact historical replay without another effect; owning link review behind a real public claim append; owning review behind a real public link revision; and migration administrator/lowered administrator/runtime role/schema/RLS scope boundaries with two projects sharing keys.

Both review cases first establish an allowed baseline, then retain the real public writer transaction immediately before COMMIT. An independent observer must see `pg_stat_activity` Lock and nonempty `pg_blocking_pids` for the blocked reviewing session before the writer commits. Review must then deny stale_claim or stale_links, including through a fresh pool. Only the baseline checked-review audit may commit; denied review audits must roll back. Claim/link storage revisions and valid audit history are checked. These cases deliberately use an empty link set to isolate owning revision consistency: they provide no evidence or source-scanner/selector/network qualification.

This checkpoint requires actual PostgreSQL17 CI before network acceptance. Local ordinary tests and strict compilation are distinct from network execution; this host has no local PostgreSQL/Docker. Current Identity, authenticated Evidence delivery, consent/rights, independent pair/link-write contention, production host credentials, remote TLS/failover/throughput/multinode/crash and distributed action fencing remain unqualified. Trusted Context/GUC scope is not authentication. Runtime, stable SDK/domain/Identity pins, contracts and migrations are unchanged. No provider/send/publication/payment/PAM work.
